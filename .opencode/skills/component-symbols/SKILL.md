# Символы компонентов EWR

Скил для подключения готовых SVG из `Site/components/` к **существующим**
плиткам палитры редактора. Главное правило: **не добавлять новые компоненты**,
а сливать исходный символ с уже существующим id.

## Когда применять

- В `Site/components/` появились папки `ewb-*` (экспорт Component-editor).
- Нужно заменить плейсхолдер (`createPlaceholderSymbol`) реальным `symbol.svg`.
- Нужно поправить `manifest.json` после замены символа.
- Нужно проверить, что порты/размеры не разъехались.

## Жёсткие правила

1. **Не добавлять новые id в палитру** (`Site/logic/js/interface.js`).
   `ewb-*` — это источники/provenance, а не имена компонентов редактора.
2. **Не редактировать** `EWB512/`, `extracted_assets/`, `Site/img/` и
   `Component-editor/elements/` — это read-only референсы.
3. **Не удалять** исходные папки `ewb-*`: на них ссылается поле
   `manifest.source` и режим «Слияние» студии.
4. **Один смысл — один id.** Резистор → `resistor`, конденсатор → `capacitor`,
   земля → `point`, генератор сигналов → `generator`. Не создавать
   `resistor2`, `ground`, `vsource` без явного разрешения владельца.
5. Комментарии/документация — по-русски, идентификаторы и пути — латиницей.

## Рабочий процесс

### 1. Понять, что изображено

Читай в таком порядке:

1. `Site/components/<ewb-id>/description.txt` — человеческое описание.
2. `symbol.svg` — геометрия и `viewBox`.
3. `source.png` / `icon.png` — как элемент выглядит в EWB.
4. `manifest.json` — размер, порты, роли, направления.

Ориентируйся на **смысл и число выводов**, а не на имя папки. Например,
`ewb-3001-05` — управляемый источник синуса (2 вывода), а не мультиметр.

### 2. Найти существующий id палитры

- `Site/logic/js/interface.js` → `idListComponent` — единственный допустимый
  список id плиток.
- `Component-editor/js/merge.js` → `CATEGORY_ELEMENTS` — те же id с подписями.
- `Site/logic/js/sim.js` → `mapComponentType` и
  `Site/engine/ewb-facade.js` → `mapEditorType` — как id понимает движок.

Если для символа нет существующего id — **не подключай его**. Зафиксируй это
в плане/ответе: для него потребовался бы новый компонент, а это запрещено без
запроса владельца.

### 3. Скопировать символ в целевую папку

```bash
cp Site/components/<ewb-id>/symbol.svg Site/components/<target-id>/symbol.svg
```

Если папки `<target-id>` ещё нет (но id уже есть в палитре) — создай её и
`manifest.json`.

### 4. Обновить manifest.json

Контракт (`Site/logic/js/registry.js`):

- `id` — **целевой** id палитры (`resistor`, а не `ewb-3002-02`);
- `symbol: "symbol.svg"`;
- `size.w/h` — **равны** `viewBox` ширине/высоте символа. Иначе порты и
  рамка компонента разъедутся: registry считает проценты от viewBox.
- `ports[].x/y` — в координатах того же `viewBox`; `dir` — `left|right|up|down`;
  роль — `in|out|inout`.
- `source` — исходная папка (`ewb-…`) для прослеживаемости;
- `parameters` **сохраняй** от старого манифеста (например, у резистора ключ
  `resistanse` — историческая опечатка-контракт, не исправляй в одиночку).

Порты и `size` бери из исходного `Site/components/<ewb-id>/manifest.json`
(они уже в системе координат его `viewBox`).

### 4.1. Размер на холсте — фиксированный мировой (без привязки к окну)

Целевой размер — **не «натуральный» viewBox**, а фиксированный мировой размер:

- при размещении `registry.js` вызывает `worldSymbolSize(size)`;
- `WORLD_SYMBOL_MAX = 100` — максимальная сторона символа в мировых px;
- пропорции символа сохраняются (масштабируется всё поле целиком, см.
  `Site/logic/js/viewport.js`);
- размер не зависит от размера окна — окно/зум не искажают компонент и порты.

Не хардкодь в манифесте пиксели «под экран». Тест `test/components.test.mjs`
проверяет фиксированный мировой размер и сохранение пропорций.

### 4.2. Обрезка пустого viewBox

Если символ занимает <50 % своего viewBox (как было у конденсатора: рисунок
166×260 внутри 800×800), обрежь поля в **целевой копии**:

1. Сними bbox рисунка (рендер `rsvg-convert` 1:1 или `A.crop.fitToContent()`
   в Component-editor).
2. Оставь поля 8–12 px, чтобы кружки портов 10 px не обрезались.
3. Поставь `viewBox="0 0 w h"` и внешнюю группу
   `<g transform="translate(-cropX -cropY)">`.
4. Пересчитай `manifest.size = {w,h}` и `ports[].x/y = старые − cropOrigin`.

Нормальный результат: рисунок занимает ~70–80 % viewBox. Исходные `ewb-*`
папки при этом не переписывай — правь только целевые копии.

### 5. Подключить к открытию `.ewb` (если применимо)

`Site/logic/js/file-io.js` → `EDITOR_MAP`:

- `resistor → resistor`, `capacitor → capacitor`, `ground → point` — можно.
- `vsource → generator` — **нельзя** без переработки: `generator` — инструмент
  с 3 портами, а `vsource` в `.ewb` — 2 терминала.

### 6. Проверить

```bash
npm test
```

Обязательный тест — `test/components.test.mjs`:

- у ключевых id есть `symbol.svg` и правильный `source`;
- `manifest.size` ↔ `viewBox`;
- порты внутри `viewBox`;
- компонент на холсте имеет фиксированный мировой размер (не зависит от окна);
- `ewb-*` не попали в `interface.js`.

Быстрая ручная проверка: открыть `Site/EWR.html` на Live Server (`:5502`),
кликнуть категорию **Компоненты** / **Приборы**, перетащить элемент — должен
рисоваться реальный символ, порты — на выводах.

### 7. Обновить план

По правилам `AGENTS.md`: подпункт = файл в `docs/engine/plans/`, строка в
`plans/README.md`; при завершении — отметка в `docs/engine/PLAN.md`.
Для этой задачи уже есть `docs/engine/plans/I2-component-symbols.md`.

## Частые ошибки

- **Скопировали `manifest.json` из `ewb-*` целиком** → в палитре появился
  чужой `id`/`name`/`category`. Меняй `id` на целевой, `source` оставляй.
- **Оставили старый `size`** → порты уезжают за пределы символа или символ
  растягивается. `size` всегда равен `viewBox`.
- **Оставили пустой viewBox 800×800** → рисунок крошечный, рамка огромная.
  Обрежь поля в целевой копии и пересчитай порты.
- **Захардкодили пиксели под конкретный экран** → на другом окне компонент
  перестаёт попадать в 15–20 %. Используй `fitSizeToViewport`.
- **Добавили `ewb-*` в `idListComponent`** → в меню появляются дубликаты.
- **Спутали `point` и землю** → в движке `point` уже маппится в `ground`
  (`mapComponentType`/`mapEditorType`), поэтому земля подключается к `point`.
- **Поменяли `resistanse` на `resistance`** → сломались `file-io.js` и меню
  параметров; переименование требует миграции.
