# AGENTS.md — правила работы в EWR

> Автозагружаемые инструкции OpenCode. Здесь только правила, команды запуска и
> протокол работы с планами. Сами планы — в отдельных файлах (см. «Планы»).
> Актуальный статус проекта в этом файле не дублируется.

## Проект

**EWR** — clean-room среда моделирования электронных схем, совместимая с
**Electronics Workbench 5.12**. В репозитории: реверс формата `.ewb` и инструменты
(`tools/`), фронт-редактор (`Site/`), legacy-движок (`Site/engine/`) и порт предка
XSPICE32 (`Site/engine/spice/`). Что сделано и что дальше — только в планах.

## Жёсткие правила (не нарушать)

1. **Clean-room.** Не копируй оригинальный код/ассеты EWB. Совместимость — только по
   наблюдаемому поведению и открытому формату файлов. См. `DISCLAIMER.md`.
2. **Билд только под тесты.** Запрещено трогать производственный конвейер сборки/деплоя
   (Vite, `.github/workflows` и т.п.). Разрешены тестовый харнесс и tooling под него.
3. **Референс оригинала** (`EWB512/`, `extracted_assets/`, `Site/img/`) — только
   read-only. Эти пути в `.gitignore`: не коммитить и не редактировать.
4. **Тесты фиксируют контракт, а не баги.** Не закрепляй известные дефекты как «эталон»
   (например, «мусорные» ведущие байты Type-1). Баги описываются в плане/`docs/re/`.
5. **Никаких секретов в конфиге.** Ключи/токены — через `{env:...}`/OAuth, не хардкодь.
6. **Стиль:** язык UI и комментарии — русский; идентификаторы кода и пути — английский.
   Держись стиля окружающего кода.
7. **Плановая дисциплина.** Не начинай подпункт плана без отдельного файла плана
   (см. ниже). Незавершённая работа без обновлённого плана считается невыполненной.

## Как запускать

| Что | Команда / где |
|---|---|
| Тесты | `npm test` (`node --test`, 0 зависимостей; self-skip если нет `EWB512/`) |
| Демо движка | `http://localhost:5502/engine/demo.html` (Live Server, root=`Site/`) |
| Открыть/сохранить `.ewb` | кнопки **Open**/**Save** в `Site/EWR.html` |
| Мост к редактору | `Site/logic/js/sim.js` (`window.EWR_SIM`), `file-io.js` |
| Декод `.ewb` → текст | `node tools/ewb2txt.mjs <file.ewb>` |
| Секции + чек-сумма | `node tools/ewb2txt.mjs --info <file.ewb>` |
| Декод папки | `node tools/ewb2txt.mjs --dir <папка> [--info]` |
| PE-экспорты (RE) | `node tools/pe-exports.mjs <file.dll\|exe>` |
| Оракул (Wine + DLL) | `node tools/oracle/run.mjs --enumerate` |
| Фронт (Site / Component-editor) | VS Code Live Server :5502 / :5501 |

Node >= 18 (проверено на 22). ESM (`package.json` → `"type": "module"`).

## Планы

### Иерархия

| Уровень | Файл | Назначение |
|---|---|---|
| Глобальный план проекта | `docs/engine/PLAN.md` | статус, фазы, приоритеты |
| Глобальный план клона движка | `docs/engine/PLAN-CLONE.md` | стратегия порта XSPICE32, критерии «1:1» |
| Индекс подпланов | `docs/engine/plans/README.md` | таблица «ID → файл → статус» |
| План подпункта | `docs/engine/plans/<ID>-<slug>.md` | детальный план конкретной работы |
| Шаблон | `docs/engine/plans/_TEMPLATE.md` | скелет плана подпункта |

**Правило:** один подпункт глобального плана = один файл плана подпункта. Глобальные
планы отвечают на вопрос «что и в каком порядке», файл подпункта — «как именно и на
каком мы этапе».

### Создание плана подпункта

1. Возьми ID из глобального плана (`P1.2`, `P2.1`, `I3`, …) и короткий латинский
   slug в kebab-case: `P1.2-ckt`, `P2.1-diode`, `I3-voltmeter`.
2. Создай файл из шаблона: `docs/engine/plans/_TEMPLATE.md` →
   `docs/engine/plans/<ID>-<slug>.md`.
3. Заполни обязательные разделы: цель, границы (что **не** входит), источники и
   референсы (файлы `vendor/`, `docs/re/`), шаги-чекпойнты, критерии приёмки, тесты,
   риски/квирки, журнал.
4. Добавь строку в `docs/engine/plans/README.md` (ID, ссылка, статус, артефакт).
5. Только после этого начинай изменения в коде.

### Ведение плана

- Статусы: `planned` → `in-progress` → (`blocked`) → `done` / `dropped`.
- Обновляй файл подпункта после каждого значимого шага: чекпойнты, журнал (дата,
  что сделано, результат `npm test`), найденные квирки.
- При завершении: статус `done`, ссылки на артефакты и тесты; строку статуса в
  глобальном плане обнови **отдельным** изменением.
- Меняется объём/порядок работ — сначала правь глобальный план, затем файл подпункта.
- Завершённые планы не удаляй: это история решений.
- Крупный подпункт можно дробить на `<ID>.1-<slug>`, `<ID>.2-<slug>` со ссылками
  из родительского файла.
- В план не копируй содержимое глобальных планов и не превращай его в дневник:
  только решения, шаги, критерии и результаты.

## Карта репозитория (коротко)

- `Site/engine/` — движок: legacy (`analysis.js`, `netlist.js`, `parser.js`,
  кодек/сериализатор) и порт предка (`spice/`).
- `Site/logic/js/` — обвязка редактора: `file-io.js` (open/save/new), `sim.js`
  (мост `EWR_SIM`), `wires.js`, `registry.js`, `drag-and-drop.js`, `interface.js`.
- `Site/components/` — символы компонентов (`manifest.json` + `symbol.svg`).
- `Component-editor/` — редактор SVG-символов.
- `tools/` — RE-утилиты (`ewb2txt.mjs`, `pe-exports.mjs`, `models-parse.mjs`),
  оракул (`tools/oracle/`), golden-харнесс sparse (`tools/sparse-golden/`).
- `docs/re/` — контракт формата `.ewb` и паспорта движка (lineage/behavior/parts/quirks).
- `test/` — golden-тесты кодекa, моделей, оракула; `Site/engine/test/` — тесты движка.

## OpenCode в этом проекте

- Инструкции: этот `AGENTS.md` (авто) + `docs/engine/PLAN.md` + `docs/engine/plans/README.md`
  (через `instructions` в `opencode.jsonc`).
- Подагенты: `explore` (быстрый поиск), `general` (многошаговые задачи).
- Коммит и пуш — только с подтверждением пользователя.

## Definition of Done (для любого изменения)

- [ ] `npm test` — зелёный.
- [ ] План подпункта обновлён; при смене статуса — обновлён глобальный план.
- [ ] Новое поведение покрыто тестом (или обосновано, почему не нужно).
- [ ] Стиль/язык соблюдены; комментарии на русском.
- [ ] Не затронуты reference-ассеты, `vendor/` и производственный конвейер.
- [ ] При изменении формата/кодека/поведения движка — обновлён `docs/re/`.
