# P1.2 — CKT-скелет (узлы, элементы, модели, задачи, диспетчер анализов)

> Родительский план: `docs/engine/PLAN-CLONE.md` (§4, фаза P1, P1.2)
> Статус: `planned`
> Начат: — · Обновлён: 2026-10-25
> Артефакты: `Site/engine/spice/ckt.js` (+ тесты `Site/engine/test/ckt.test.mjs`)

## Цель

Портировать скелет `CKT` из SPICE3F4/XSPICE: реестр узлов и элементов, модели,
задачи (`task`) с дефолтами опций, диспетчер анализов (`CKTdoJob`/`CKTfndAnal`).
Это фундамент, на который дальше лягут Ньютон (P1.3) и устройства (P1.4+).

## Границы (что не входит)

- Ньютон, интеграция, LTE-шаг — P1.3.
- Устройства и их штамповка — P1.4–P1.6.
- XSPICE MIF/цифра — фаза X.
- Мост к редактору (`ewb-facade.js`) — фаза I.

## Источники и референсы

- `vendor/spice3f4/src/lib/ckt/` — `cktinit`, `cktntask`, `cktnewelem`, `cktnewnode`,
  `cktnewmod`, `cktdojob`, `cktop`, `ckttran`, `cktdist`, `cktac`, `cktnoise` и др.
- `vendor/xspice-1-0/src/sim/CKT/` — версия XSPICE (дефолты `CKTnewTask`, `trtol=1.0`).
- `docs/re/engine-behavior.md` §4.2 — снятые оракулом дефолты task-опций
  (`gmin=1e-12`, `reltol=1e-3`, `abstol=1e-12`, `vntol=1e-6`, `trtol=1.0`,
  `chgtol=1e-14`, `pivtol=1e-13`, `tnom=temp=300.15`, `itl1=100`, `itl2=50`, `itl4=10`).
- `tools/oracle/golden/enum.json` — список 84 устройств / 10 анализов / опций DLL.
- `Site/engine/spice/sparse.js` — контракт матрицы (P1.1).

## Шаги / чекпойнты

- [ ] Определить публичный контракт модуля (ESM): `cktInit`, `cktNewNode`,
      `cktCrtElt`, `cktNewTask`, `cktNewAnal`, `cktDoJob`, `cktFindDev`; структуры
      `CKThr`, `CKTnode`, `CKTcircuit`, `CKTtask`, `CKTanalysis` — по C, без DOM/Node API.
- [ ] Реестр устройств: таблица «имя → дескриптор» с хуками `setup/temp/load/acLoad`,
      пока пустыми заглушками (реальная штамповка — P1.4+).
- [ ] Реестр анализов: `op/dc/tran/ac` как минимум; неизвестные — понятная ошибка.
- [ ] Task + дефолты опций строго по `engine-behavior.md` §4.2 (включая `trtol=1.0`).
- [ ] Диспетчер `cktDoJob`: выбор анализа, инициализация, вызов задачи; коды ошибок.
- [ ] Точки расширения EWB-швов (`getVoltage/getCurrent/getMatrixElement/setMaxStep`)
      объявить в API, реализацию — в фазе I.
- [ ] Юнит-тесты: создание узлов/элементов, дефолты task, поиск анализа/устройства,
      ошибки на неизвестном типе.

## Критерии приёмки

- [ ] Из кода можно собрать цепь (узлы + элементы-заглушки) и вызвать `cktDoJob('op')`
      без падения; диспетчер выбирает нужный анализ.
- [ ] Дефолты опций task совпадают с `tools/oracle/golden/enum.json` /
      `docs/re/engine-behavior.md` (проверяется тестом).
- [ ] `npm test` зелёный; старые 84 теста не сломаны.

## Риски и квирки

- Расхождение F4 ↔ XSPICE в дефолтах (`trtol`) → брать значения DLL
  (`engine-behavior.md`), а не F4.
- Порядок обхода узлов/элементов влияет на пивоты и последние цифры → в P1.2
  зафиксировать структуру, а порядок сверять с оракулом в P1.6.
- Новые квирки — в `docs/re/engine-quirks.md` с ID.
