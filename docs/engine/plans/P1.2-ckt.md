## Цель

Портировать скелет `CKT` из SPICE3F4/XSPICE: реестр узлов и элементов, модели,
задачи (`task`) с дефолтами опций, диспетчер анализов (`CKTdoJob`/`CKTfndAnal`).
Это фундамент, на который дальше лягут Ньютон (P1.3) и устройства (P1.4+).

## Границы (что не входит)

- Ньютон, интеграция, LTE-шаг — P1.3. **Уточнение:** в P1.2 вошли
  `NIinit`/`NIreinit`/`NIdestroy` (создание матрицы и RHS-векторов) — без них
  `CKTsetup`/`CKTic`/`CKTdoJob` неработоспособны; сам `NIiter`/`NIintegrate`/
  `NIconvTest`/LTE — P1.3.
- Устройства и их штамповка — P1.4–P1.6. В реестре только метаданные DLL
  (индекс/имя/описание/выводы) и `null`-хуки `SPICEdev`.
- Реализации анализов — P1.6 (`OP`/`TRAN`) и P3 (остальные). В P1.2 анализам
  соответствует `an_func = analysisNotImplemented` → `E_UNSUPP` с текстом в
  `ckt.errMsg` (чтобы «пустой» прогон нельзя было спутать с успешным расчётом).
- XSPICE MIF/цифра (`evt`/`enh`, код-модели) — фаза X.
- Мост к редактору (`ewb-facade.js`) и EWB-швы (`getVoltage`/`getCurrent`/
  `getMatrixElement`/`setMaxStep`) — фаза I; в P1.2 они объявлены и возвращают
  `E_UNSUPP`.

## Решения по ходу порта

| Вопрос | Решение | Почему |
|---|---|---|
| Каталог устройств/анализов | `catalog.js` генерируется из `enum.json`; индексы = `type` в CKT API | порядок/имена обязаны совпадать с DLL; ручное дублирование 84 строк — источник расхождений |
| `CKTsetup` | F4-редакция: `NIinit` + `CKTisSetup=1` + `E_NOCHANGE` при повторе | lineage: числовое ядро DLL — F4; XSPICE-редакция отличается — Q-C01 |
| `trtol` | `CKTnewTask = 1.0` (XSPICE/DLL), `CKTinit = 7` (F4) | как в источниках; `CKTdoJob` копирует task → ckt, поэтому расчёт идёт с 1.0 |
| `CKTnewAnal(type=0)` | job = сама task, в `task.jobs` не добавляется | 1:1 `cktnewan.c` |
| Порядок анализов | внешний цикл по `ANALYSES`, внутренний по `task.jobs` (LIFO) | «Analysis order is important» из `cktdojob.c` |
| Ошибки | коды `iferrmsg.h`; текст в `ckt.errMsg`/`ckt.errRtn` | в C это глобалы `errMsg`/`errRtn`; per-circuit безопаснее для тестов/параллельных прогонов |
| Хуки устройств | сигнатуры C; `state={value}` вместо `int*`; `DEVdestroy(ckt,type)` вместо `GENmodel**` | в JS нет указателей; контракт зафиксирован в JSDoc `ckt.js` |
| `CKTic` без setup | `E_BADMATRIX` + текст | в C — segfault; в P1.2 без устройств матрица может быть ещё не размечена |

## Риски и квирки

- **Q-C01 (открыто):** `CKTsetup` в F4 и XSPICE различается (`NIinit`/`CKTisSetup`/
  `E_NOCHANGE`). Выбран F4-вариант; сверить с DLL оракулом в P1.6 (двойной
  `doAnalyses(reset=1)` и поведение `CKTisSetup`). Запись — `docs/re/engine-quirks.md`.
- Расхождение F4 ↔ XSPICE в дефолтах (`trtol`) → берём значения DLL
  (`engine-behavior.md`), а не F4.
- Порядок обхода узлов/элементов влияет на пивоты и последние цифры → в P1.2
  зафиксирована структура (список `CKTnodes`, LIFO моделей/инстансов), порядок
  сверяется с оракулом в P1.6.
- `CKTic` в P1.2 защищён от «короткого» RHS (`E_BADMATRIX`); после P1.3/P1.4
  device-setup размечает матрицу, и защита не срабатывает.
- Новые квирки — в `docs/re/engine-quirks.md` с ID.
