## Цель

Портировать диод SPICE3 1:1 в редакции XSPICE32 (EWB-сборка): модель,
температурную подстройку, DC/TRAN-загрузку, AC-нагрузку, LTE-шаг, сходимость,
внутренний узел `rs`, пробой/зенер. Получить паритет OP/TRAN/AC с оракулом.

## Границы (что не входит)

- Noise/Disto/PZ/Sensitivity-хуки (`DIOnoise`, `DIOdisto`, `DIOpzLoad`,
  `DIOsAcLoad`, `DIOsSetup`, `DIOsUpdate`) — фазы P3.
- `DEVgetic` в этой сборке не вызывается (см. `cktIc`); UIC-путь диода
  использует `DIOinitCond`/`DIOoff`, как в F4.
- BJT/MOSFET/оп-ампы — P2.2–P2.5.

## Риски и квирки

- Внутренний узел при `rs != 0`: в C имя даёт `IFnewUid(..., "internal")`;
  шим оракула суффикс игнорирует (Q-O02) — нормализуем в тесте, golden не
  правим.
- `DIOload` при `MODEINITSMSIG` делает `continue` до штамповки — это не баг,
  а контракт AC/OP (значения уже в состояниях).
- Порог пробоя `vd < min(0, -bv + 10*vte)` и `tBrkdwnV` считать строго по C:
  `tBrkdwnV = bv - vt*log(1 + ibv/isat)` — **меньше** `bv` (на `bv=5`,
  `ibv=1e-3`, `is=1e-14` ≈ 4.345 В).
- **Q-D05**: DLL собрана с `NOBYPASS` — опция `bypass` не действует, состояние
  диода после OP равно последнему решению. Без этого AC расходится.
- **Q-D06**: `NEWCONV` — проверка сходимости диода по току не компилируется;
  сходимость даёт только `Check` + `NIconvTest` по узловым напряжениям.
- **Q-O03**: `STATnumIter` DLL вдвое больше нашего — не воспроизводим (не
  влияет на результаты, тестами не сверяется).
